# P4：AiRMS 控制頁 airms.html（讀取與設定 AiRMS 設備）

完成日期：2026-11-07

取代舊 starter 的 airms.html（新頁面沿用同一個檔名）：路網圖同即時監視頁，下方可讀取與設定 AiRMS 設備的「儀控敏感性」與「AiRMS 開/關」。
與設備之間的指令沿用舊系統，不需要改設備。

## 內容

| 元件 | 說明 |
|---|---|
| `control/AirmsProtocol` | 設備指令格式（見下方）、回覆解析、敏感性與位址檢查 |
| `control/AirmsClient` | 與設備的 TCP 對話：每次一條新連線，送一筆、收一筆後關閉（同舊系統）。同一時間只跟設備進行一段對話，其他要求排隊；多個畫面同時讀取時共用同一次查詢 |
| `control/AirmsControlService` | 讀取狀態（不寫資料庫）、送出設定並記錄 |
| `http/ControlApi` | `GET /api/airms/status`、`POST /api/airms/settings`、`GET /api/airms/log` |
| `webroot/airms.html`、`js/airms.js` | 控制頁；路網圖與即時監視頁共用 `js/live-map.js` |
| core.db 版本 2、3 | 新增 `airms_control_log`（設定紀錄；版本 3 加上「送出前」讀到的時間 `before_at_ms`），舊的 core.db 啟動時自動升級；升級後若改回 0.3.x 會因版本較新而拒絕啟動，要退版請先還原升級前的 core.db 備份 |
| 系統設定「AiRMS 設備」 | 設備 IP（或主機名稱）與 TCP port，可在網頁上改，下一次讀取或送出就生效 |
| `tools/airms-sim/airms_sim.py` | 開發測試用的設備模擬器（只用 Python 標準函式庫） |

## 設備指令（沿用舊系統）

每次連線送 6 個 ASCII 字元、收 6 個字元，收到就關閉連線。

| 動作 | 送出 | 設備回覆 |
|---|---|---|
| 查詢 | `01,000` | `91,SSX` |
| 設定 | `02,SSX` | 成功 `92,SSX`；設備無法設定 `99,000` |

`SS` 為兩位數的儀控敏感性（畫面限制 40～80、每次 5），`X` 為 AiRMS 開（1）／關（0）。

## 權限

- AiRMS 控制頁與 `/api/airms/*` 一律要登入、已變更初始密碼，且有「AiRMS 控制」權限（管理者本來就有）。
  不受系統設定「首頁與即時監視需要登入」影響。
- 有「AiRMS 控制」權限就能看路網圖（`/api/view/*`），也能開即時監視頁，不必另外勾「監視」。
- 沒有權限的帳號：左側選單不顯示「AiRMS 控制」，首頁卡片顯示「目前帳號沒有這個權限」，直接開網址得到 403。
- 送出設定與其他寫入一樣要帶 CSRF token；送出前的確認沿用舊系統「確定送出？」，不再輸入密碼。

## 畫面操作

- **開頁**：畫路網、載入一次即時資料，並讀一次設備狀態。
- **開始監控**：路網依「間隔更新時間（秒）」（預設 25，10～600）、設備依「參數輪詢間隔時間（秒）」（預設 180，最少 30，同舊系統）
  定時更新；按下時立即各更新一次，再按一次停止。監控中兩個間隔不能改。
- **設備目前狀態**：敏感性、ON／OFF、讀取時間、設備位址；讀取失敗時保留上一次的值（變淡）並顯示原因。「立即讀取」隨時可按。
- **設定**：參數一用滑桿或 −／＋ 調整敏感性，參數二用開關；改過還沒送出時顯示「尚未送出」，這時輪詢不會蓋掉畫面上的設定值
  （舊頁面會蓋掉），可按「還原為設備目前值」放棄修改。
- **送出 (Submit)**：跳出確認視窗，列出要送出的值與設備目前的值，按「送出」才送。送出期間按鈕停用。
  成功後設定值與設備狀態都更新成設備確認的值；失敗時保留畫面上的設定值，可以再送一次。
- **AiRMS 參數紀錄摘要**：最近 5 筆輪詢與設定結果（同舊頁格式，例如「10:22:33 輪詢。敏感性：60，AiRMS：ON。」），
  只存在這個畫面，重新整理就清空。
- **設定紀錄**：開啟最近 30 天所有人送出的設定（伺服器記錄，見下方）。
- 寬螢幕（1200×700 以上）路網圖會依剩餘高度縮放，整頁不必捲動；手機上改為上下排列。

## 送出設定的流程與結果

同舊系統，按「送出」只送一筆設定指令 `02,SSX`，不先查詢。紀錄的「送出前」是伺服器最後一次得知的設備狀態
（任何畫面最近一次讀取成功，或上一筆設定設備確認的值）與當時的時間；程式重啟後還沒讀過、或換了設備位址，記為「未知」。
多人同時送出時依序排隊，「送出前」取輪到這一筆時已知的狀態。依設備回覆判斷：

| 結果 | 說明 |
|---|---|
| 完成 | 設備回 `92`，且值與送出的相同 |
| 設備無法設定 | 設備回 `99,000`（舊系統訊息「系統異常,無法設定」） |
| 設備確認的值不同 | 設備回 `92`，但值與送出的不同（畫面顯示設備回的值） |
| 尚未設定設備位址 | 系統設定的設備 IP 是空白 |
| 無法連線 | 連線失敗（會再試 2 次，間隔 300 毫秒） |
| 設備沒有回應 | 連上後超過 `responseTimeoutMs` 沒收到完整回覆 |
| 回覆格式不對 | 收到的不是預期的 6 個字元（可接受結尾多一個換行） |

每次送出不論結果都寫一筆 `airms_control_log`（時間、帳號、來源 IP、設備位址、送出前與讀到的時間、送出的值、設備確認的值、
結果、設備原始回覆、花費時間），並在「登入管理 → 操作紀錄」記一筆「AiRMS 設定送出」。讀取（輪詢）不寫資料庫，
只在 log 檔記錄。設定紀錄目前不會自動刪除（每次送出才一筆，量很小）。

## 設定

`config.json`（選填，沒有這一段就用預設值）：

```json
"airmsDevice": {
  "host": "",
  "port": 9876,
  "connectTimeoutMs": 2000,
  "responseTimeoutMs": 5000
}
```

- `host`、`port` 是預設值，管理者可在「系統設定 → AiRMS 設備」改（存在 core.db，改了留操作紀錄，按「還原預設」回到 config.json 的值）。
  `host` 空白表示尚未設定，AiRMS 控制頁會顯示「設備位址未設定」。範本不放實際位址；舊系統的位址在 starter 的 PTConfig.json `tcp` 段。
- `connectTimeoutMs`（100～30000）、`responseTimeoutMs`（500～60000）只能在 config.json 改，重啟生效。
  設備連得上但不回覆時，一次讀取或送出最久等 `responseTimeoutMs`。

## 開發測試：設備模擬器

```
python tools/airms-sim/airms_sim.py                       # 127.0.0.1:9876，敏感性 60、ON
python tools/airms-sim/airms_sim.py --port 9877 --sensitivity 55 --off
python tools/airms-sim/airms_sim.py --mode refuse-set     # 設定一律回 99,000
python tools/airms-sim/airms_sim.py --mode silent         # 不回覆（測逾時）
python tools/airms-sim/airms_sim.py --mode garbage        # 回覆格式錯誤
python tools/airms-sim/airms_sim.py --delay 2             # 每次延遲 2 秒回覆
```

在模擬器視窗輸入 `normal`、`refuse-set`、`silent`、`garbage` 可直接切換模式，`status` 看目前的值，`quit` 結束。
系統設定把設備 IP 設為 `127.0.0.1`、port 設成模擬器的 port 即可測試。預設只聽本機，不要在正式網路上執行。

## 測試

- `AirmsClientTest`：指令格式與回覆解析、位址檢查；用測試內的假設備測正常讀取／設定、`99`、回覆分段到達、
  結尾換行、格式錯誤、逾時、中途斷線、連不上、未設定；同一時間只有一段對話、同時讀取共用一次查詢、
  設定之後才要求的讀取不會拿到設定前的結果；設定只送 `02`、「送出前」取最後讀到的值、換設備位址後不沿用前一台的值。
- `AirmsControlServiceTest`：每種結果都寫入設定紀錄與操作紀錄、查詢紀錄的區間與筆數。
- `AppConfigTest`、`SettingsServiceTest`：`airmsDevice` 與「AiRMS 設備」設定的預設值與檢查。
- 瀏覽器實測（模擬器）：讀取、調整後輪詢不覆蓋、確認視窗取消／送出、設備無法設定、沒有回應、連不上、
  系統設定改 port／清空位址、權限（沒有權限 403、未登入轉登入頁、必須先改密碼）、沒有 CSRF token 被拒、
  1366×768 與手機寬度版面、CSP 沒有違規。

## 與舊程式對接測試（2026-11-07）

用舊 starter 的 jar（starter-1.3.3-SNAPSHOT-fat.jar，程式不修改）實際執行舊的程式碼，與新程式互相對接：
舊的設備模擬器（`Server.startTestTCPServer`）、舊 airms.html 呼叫的讀取與設定（`/getAiRMSSensitivity`、`/startTCPConnect`）
都用反射直接呼叫舊的方法，只把帳密換成測試用的。新程式為 0.4.0 的 `/api/airms/*`（回覆逾時設 2 秒）。

| 情境 | 舊程式 | 新程式 |
|---|---|---|
| 舊模擬器：讀取（起始 40／OFF） | 40／OFF | 40／OFF |
| 舊模擬器：舊程式設 55／ON 後新程式讀 | 55／ON | 55／ON |
| 舊模擬器：新程式設 70／OFF 後舊程式讀 | 70／OFF | 70／OFF |
| 舊模擬器：新程式送 40～80 每 5、ON／OFF 共 18 次，每次用舊程式讀回 | 18 次都讀到新程式送的值 | 18 次都成功 |
| 新模擬器（airms_sim.py）：讀取、互相設定再讀 | 都正確 | 都正確 |
| 設定時設備回 99,000 | 系統異常,無法設定 | 設備無法設定（99,000） |
| 設備收到指令不回覆 | 一直等，畫面沒有結果 | 逾時後顯示「設備沒有回應」 |
| 設備回覆格式錯誤 | 一直等（舊程式解析時發生例外，沒有回應） | 「回覆的格式不對」並顯示收到的內容 |
| 查詢時設備回 99,000 | 顯示「敏感性 0，OFF」（誤判為成功） | 「設備回覆系統異常，無法讀取狀態」 |
| 回覆分兩段到達 | 資料格式錯誤 | 正確讀到 |
| 設備沒開 | 連線失敗 | 無法連線 |

第一次測試時新程式在設定前會先送一次 `01,000` 查詢；依使用者決定（2026-11-07）改成同舊程式只送 `02,SSX`，
重測後舊模擬器收到的指令與舊程式完全相同（讀取 `01,000`、設定 `02,SSX` 各一條連線）。

## 與舊系統的差異

| 項目 | 舊系統的 airms.html（starter） | 新的 airms.html |
|---|---|---|
| 登入 | 頁面內另外登入，帳密存在瀏覽器 sessionStorage，每次讀取／送出都帶帳密 | 用系統帳號登入（P2），需「AiRMS 控制」權限，不再傳送密碼 |
| 輪詢時 | 會蓋掉畫面上還沒送出的設定值 | 有未送出的修改時不蓋掉，另外顯示設備目前值 |
| 設備指令 | 讀取送 `01,000`、設定送 `02,SSX` | 相同（設定前不另外查詢） |
| 紀錄 | 只有畫面上的 5 筆摘要 | 另有伺服器端設定紀錄（含送出前最後讀到的值與時間、設備回覆、操作者、IP）與操作紀錄 |
| 設備位址 | PTConfig.json，改了要重啟 | 系統設定頁可改，立即生效 |
| 同時多人 | 各自連線，可能同時對設備送指令 | 伺服器排隊，同一時間只有一段對話 |
| 「屏柵線 流量輸出」按鈕 | 有 | 不在這頁（未列入 P4） |
