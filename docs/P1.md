# P1：資料抓取與保存

完成日期：2026-11-02

## 內容

| 元件 | 說明 |
|---|---|
| `AirmsApplication` / `MainVerticle` | Vert.x 5 啟動；讀設定 → 檢查外接硬碟標記檔 → 開兩個資料庫並確認結構 → 啟動抓取與資料保留 → 開 HTTPS（TLS 1.3） |
| `config/AppConfig`、`Secrets` | 設定一次讀入並驗證，錯誤全部列出；密碼只從環境變數或 secrets.json 讀 |
| `storage/DataVolume` | 外接硬碟防呆：沒有 `.airms-volume` 標記檔就拒絕啟動 |
| `db/Db`、`Schema` | 每個 SQLite 檔一條寫入執行緒（同 StockVX）；WAL；`vd_health.db` 用 synchronous=FULL；以 application_id/user_version 認檔，不認得的檔拒絕使用 |
| `feed/FeedHttpClient` | 下載限制：連線/閒置逾時、整體期限、8 MB 上限、不跟隨轉址、不接受壓縮 |
| `feed/SafeXml` | 不處理 DTD 與外部實體；限制元素數、深度、屬性長度；截斷或格式錯誤整份拒絕 |
| `feed/RawXmlArchive` | 原始 XML gzip 歸檔（先寫暫存檔再改名），依收到時間（台北）分目錄 |
| `feed/FeedVerticle` | 每個來源一個；下載 → 雜湊（沒變就結束）→ 解析 → 歸檔 → 寫入 → 記錄；一輪結束才排下一輪 |
| `parse/*Parser` | VD、路段、RMS 解析；原值照存，單欄有問題只記錄不整份丟棄 |
| `repo/*Repository` | 最新表只往新時間更新；歷史表同時間只存一筆；VD 同一份內容只存一次 |
| `retention/RetentionVerticle` | 每 12 小時清除超過保留天數的路段/RMS 歷史與抓取紀錄，一天一個短交易 |
| `http/WebServer` | 資安標頭；每個回應新的隨機 CSP nonce；POST 本文 64 KB 上限、不收上傳檔；錯誤只回通用訊息；`/api/health` |

## 停機重跑的處理（2026-11-02 追加）

- `storage/DataDirLock`：同一資料目錄只允許一個程式（作業系統檔案鎖，強制結束時自動釋放）
- `service_run` 表（airms.db 版本 2，舊的版本 1 會自動升級）：啟動、每分鐘心跳、正常停止時間；上次非正常停止時 log 列出停機區間
- `RawXmlArchive`：啟動時清除 10 分鐘以上的暫存檔；同一天已有同雜湊的檔就沿用
- 驗證：24 個測試通過；端對端模擬強制結束（kill -9）後重啟 → 偵測到非正常停止、資料與歸檔檔不重複；第二個程式指向同一資料目錄 → 拒絕啟動；舊版 v1 資料庫自動升到 v2

## 和舊系統不同的地方

- RMS 某欄缺值（例如目前 RMS-N3-S-182 每分鐘缺 `rms_rate`）時：舊系統整份標為部分失敗、每分鐘重試；新系統照存該列（缺的欄位為 NULL）並記錄問題。
- 路段最新表的主鍵加上國道與方向，國1/國3 里程相同時不會互相覆蓋。
- VD 存全部約 1,486 支、3,205 個車道的 14 欄原值（-2 照存），不再只存 8 支的流量加總。
- 屏柵線告警改由 VD 原值計算（P3 實作），無效車道的時段標為資料異常，不把 -2 加進總量。
- 不再使用 MongoDB、AES 回傳加密、固定 CSP nonce、測試用 TCP 端點。
