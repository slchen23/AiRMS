# P2：帳號系統與管理工具頁

完成日期：2026-11-03

## 內容

| 元件 | 說明 |
|---|---|
| `auth.db`（新檔，與 airms.db 同目錄） | `account`、`account_permission`、`login_history`、`audit_log`；application_id 獨立，不會和其他資料庫混用 |
| `auth/PasswordHasher` | Argon2id（t=3、m=64 MB、p=1），與 StockVX 相同；雜湊在專用 worker 計算，不卡住網頁 |
| `auth/AuthService` | 初次設定、登入、登出、改密碼、帳號管理、Session 撤銷、紀錄查詢 |
| `auth/SessionRegistry` | 登入狀態只存在記憶體；Cookie 只放隨機 token，伺服器只存 token 的 SHA-256；閒置逾時（可設定，預設 30 分鐘）與最長 12 小時 |
| `auth/LoginInput`、`auth/LoginProtection` | 登入名稱檢查、同一帳號密碼錯誤冷卻（2026-11-05 改版，見下方「登入規則」；原本依來源 IP 的限制已拿掉） |
| `settings/SettingsService` | 系統設定頁可改的項目；預設值來自 config.json，修改值存在 airms.db 的 `app_setting`（airms.db 升到版本 3） |
| `http/AuthApi`、`AdminApi`、`Http` | 登入與管理 API；CSRF、來源檢查；錯誤訊息統一轉換 |
| 頁面 | `login.html`、`setup.html`、`account.html`、`admin-users.html`、`admin-sessions.html`、`admin-settings.html`、`index.html`（改版） |
| 前端 | AdminLTE 4.10、Bootstrap 5.3.8、Bootstrap Icons 1.13.2、DataTables 3.1.5，全部放在本機 `webroot/vendor/`（見 `docs/vendor.md`） |

## 第一次啟動：建立管理者

系統沒有預設帳號、預設密碼。第一次啟動（`auth.db` 裡沒有任何帳號）時，log 會出現：

```
WARN [MainVerticle] 尚未建立任何帳號。請在 30 分鐘內開啟 https://localhost:8081/setup.html ，輸入設定碼 XXXXXXXXXXXX 建立第一個管理者
```

1. 打開 `setup.html`，輸入 log 裡的設定碼、管理者帳號、顯示名稱、密碼。
2. 建立後設定碼立即失效，`setup.html` 會自動轉到登入頁。
3. 設定碼 30 分鐘內有效；逾時重新啟動程式會產生新的。

只有能看到主機 log 的人才拿得到設定碼，所以不需要另外的命令列工具。

## 角色與權限

| | 管理者 | 一般使用者 | 未登入 |
|---|---|---|---|
| 首頁、即時監視（P3，view.html） | ✓ | ✓ | ✓ |
| AiRMS 控制（P4，airms.html） | ✓ | 需勾選「AiRMS 控制」 | ✗ |
| 資料下載（P5 的 query） | ✓ | 需勾選「資料下載」 | ✗ |
| 帳號與密碼（自己的） | ✓ | ✓ | ✗ |
| 使用者管理、登入管理、系統設定 | ✓ | ✗ | ✗ |

- 「監視」權限：系統設定「首頁與即時監視需要登入」開啟（2026-11-05 起預設）時，看即時監視需要此權限（有「AiRMS 控制」權限也可以）。
  （2026-11-05 更新：首頁與即時監視改為預設需要登入，即時監視需「監視」權限；見 P3.md。）
- 管理者建立帳號時給臨時密碼，對方第一次登入必須改成自己的密碼，改完之前不能使用其他功能。
- 帳號可設定到期日（到期日當天仍可使用，隔天 00:00 起失效）與停用；停用、到期、重設密碼都會立即登出該帳號。
- 管理者不能停用自己、取消自己的管理者身分或設定自己到期，避免把自己鎖在外面。

## 管理工具頁

| 頁面 | 功能 |
|---|---|
| 使用者管理 `admin-users.html` | 帳號列表；新增、編輯（顯示名稱、角色、權限、到期日、啟用）、重設密碼、解除登入冷卻 |
| 登入管理 `admin-sessions.html` | 線上使用者（可強制登出）、登入紀錄（依日期、帳號、結果查詢）、操作紀錄（誰在什麼時候改了什麼） |
| 系統設定 `admin-settings.html` | 三個資料來源的啟用、網址、間隔；資料保留天數；閒置登出時間、密碼錯誤冷卻（次數、計算期間、冷卻時間） |

系統設定修改後立即生效（抓取在下一輪、清除在下一次執行），不需重啟。正式機改內網 XML 網址也可以直接在這裡改。
連接埠、憑證、資料目錄只能改 config.json。

## 和資安掃描報告（starter 1.3.3）待辦項目的對應

| 舊系統問題 | 新系統做法 |
|---|---|
| 前端 sessionStorage 存密碼、每次請求重送密碼 | 只在登入時送一次密碼；之後用 HttpOnly、SameSite=Strict、Secure 的 Session Cookie，前端拿不到 |
| 登入沒有暴力破解防護 | 同一帳號 300 秒內錯 5 次冷卻 60 秒（比照 EMS，可在系統設定調整）；帳號不存在時也做一次雜湊，回應時間一致，錯誤訊息一律相同 |
| CSP 固定 nonce | 每個回應產生新的 nonce（P1 已完成）；所有樣式在 css 檔，CSP 不允許 inline style |
| 前端寫死 AES 金鑰 | 不在前端做加解密，傳輸靠 TLS 1.3 |
| Trusted Types pass-through | 前端不用 innerHTML 放資料；畫面文字一律 textContent，表格字串用 DataTables 的跳脫輸出 |
| 資料 API 匿名可讀 | 監視資料依需求開放不登入；控制、下載、管理 API 一律要登入與權限，寫入要 CSRF token |
| MongoDB 無帳密 | 不再使用 MongoDB；資料庫是外接硬碟上的 SQLite 檔 |
| 設定檔明文密碼、金鑰進版控、log 進版控 | 密碼只在 secrets.json 或環境變數；config.json、secrets.json、憑證、資料庫、logs/ 都在 .gitignore；沒有預設密碼 |

其他：寫入 API 檢查 Origin、帳號名稱與輸入長度限制、登入與管理操作都寫紀錄（不記密碼）、錯誤只回通用訊息。

## 登入規則（2026-11-05 調整，比照 EMS 開發資安參考）

| 項目 | 規則 |
|---|---|
| 登入名稱 | 去掉前後空白後最多 50 個 Java 字元；含控制字元、格式控制字元（零寬空白、方向覆寫等）、行／段分隔、落單代理字元、私用區或未指派字元直接拒絕（400，不查帳號、不算密碼錯誤）。寫進登入紀錄時把這些字元換成「?」、超過 50 字截斷，結果標「帳號格式不正確」 |
| 密碼錯誤冷卻 | 同一帳號在 300 秒內密碼錯誤 5 次，從第 5 次起冷卻 60 秒；冷卻期間的嘗試不檢查密碼、不計次、**不延長冷卻**；冷卻結束後重新計算。三個數字都可在系統設定「登入安全」調整。管理者可在使用者管理頁「解除冷卻」 |
| 錯誤訊息 | 帳號不存在、密碼錯誤、冷卻中都回同一句「帳號或密碼錯誤。同一帳號 5 分鐘內錯誤 5 次，需等待 60 秒後再試。」，無法從訊息猜出帳號是否存在 |
| 不依 IP 鎖定 | 原本「同一 IP 10 分鐘錯 20 次暫停」已拿掉：經過 Cloudflare Tunnel 時所有人都是 127.0.0.1，會變成一人亂試、全部人被擋 |
| 初次設定碼 | 輸錯 10 次就作廢，需重新啟動取得新的設定碼（取代原本依 IP 的限制） |
| 一般帳號單一登入 | 一般使用者同一時間只能登入一處：已在別處登入（且未閒置逾時）時，**拒絕新的登入**（409），訊息列出原登入的時間與來源，並說明可先登出、等閒置逾時（預設 30 分鐘），或請管理者在「登入管理」強制登出。密碼正確才會告知。同一個瀏覽器重新登入不受限（舊的換成新的）。管理者不限 |
| 登入紀錄新結果 | 帳號格式不正確、已在其他地方登入（拒絕）、密碼錯誤開始冷卻、冷卻中（未檢查密碼） |

注意：一般帳號若用在開著即時監視的畫面（每 25 秒更新），那個登入不會閒置逾時，同帳號在別處會一直登不進去；監視畫面請用專用帳號，或請管理者強制登出。

## 已知限制

- **重新啟動後所有人需要重新登入**（Session 只存在記憶體）。這是刻意的：重啟後沒有殘留的登入狀態可被盜用。
- 登入紀錄、操作紀錄目前不自動清除（資料量很小）；之後若需要可加到資料保留設定。
- 修改 `webroot` 裡的頁面後要重新啟動才看得到（頁面與檔案在記憶體有快取）。

## 驗證

- 38 個測試通過（新增帳號規則、密碼雜湊、Session 期限、IP 限制、AuthService 完整流程、系統設定、auth.db 結構）。
- 端對端（HTTPS、Chromium）：初次設定 → 登入 → 新增帳號 → 解鎖 → 改設定 → 新帳號首次登入強制改密碼 → 登出；所有頁面沒有 CSP 違規或前端錯誤；手機寬度可操作。
- API 檢查：沒有 CSRF token、跨站 Origin、一般使用者呼叫管理 API、格式錯誤的 JSON 都被拒絕並回正確狀態碼。
